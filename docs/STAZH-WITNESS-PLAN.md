# Стаж на ядре Seeker Witness — план на три недели

Решено Alexом 17.09.2026 в чате «Идеи: что Seeker может дать миру». Подача 7 октября.
Основание: пробник Key Attestation на живом Seeker прошёл (грабли Seed Vault №13, `C:\attprobe`).

## Формула продукта

**Стаж — доказуемая история жизни физического Seeker.** Не карточка, которую сервер
нарисовал из API, а запись, которую телефон подписывает своим железом каждый день.

Хакатон называется CLOCK IN. Кнопка в приложении называется CLOCK IN. Каждый день
владелец жмёт её, Seeker подписывает день ключом из StrongBox, и стаж растёт.

## Четыре слоя, разделены с первого дня

| Слой | Где живёт | Что делает |
|---|---|---|
| `witness-core` | `modules/witness-core` (Expo-модуль, Kotlin) | P-256 в StrongBox с челленджем и device properties; отдать цепочку; подписать байты. Перенос из `C:\attprobe\MainActivity.java`, ~150 строк |
| `witness-verifier` | сервер SKR Eyes (VPS) | проверить цепочку до корня Google (оба корня), CRL, `brand=solanamobile`, model, `deviceLocked`, `Verified`, наш пакет + отпечаток подписи APK, срок RKP-сертификата; **вердикт хранить**, цепочку не перепроверять. Подписать вердикт ключом аттестора (ed25519). Основа — `C:\attprobe\parse2.py` |
| `witness-registry` | цепочка Solana + индексатор на сервере | запись = транзакция кошелька владельца (Seed Vault, палец) с Memo и инструкцией `Secp256r1SigVerify` от железного ключа. **Своей программы для хакатона нет** — прекомпайл нативный, деплоить нечего |
| `stazh-app` | экраны в `src/` | VERIFY MY SEEKER → Service Record → CLOCK IN → история и серия → поделиться |

Стаж — первый клиент Witness. После хакатона ядро выпускается отдельно: «The attestation layer powering Stazh is now available as Seeker Witness».

## Как это работает на пальцах

1. **VERIFY MY SEEKER.** Приложение просит у сервера челлендж, рождает ключ в StrongBox,
   отдаёт цепочку. Сервер читает печать Google: Seeker, целый, наш APK. На экране
   построчно: Solana Mobile Inc. · Seeker · StrongBox · Android 16 · Verified Boot ·
   APK verified · Hardware key registered. На эмуляторе или чужом Android — **NOT A SEEKER**.
2. **CREATE MY SERVICE RECORD.** Seed Vault через `signMessagesDetached` подписывает
   строку `witness-bind v1 | <pubkey железа> | <SGT mint>`. Сервер проверяет SIWS-подпись,
   наличие SGT (по официальному рецепту, mint запоминаем), и связывает три вещи:
   кошелёк ↔ SGT ↔ железный ключ. Первая запись уходит в цепочку: транзакция кошелька
   с Memo `witness-register v1 | <hash вердикта> | <pubkey железа>` плюс ed25519-подпись
   аттестора и secp256r1-подпись железа. Это **Genesis-запись** конкретного Seeker.
3. **CLOCK IN.** Раз в сутки: железный ключ подписывает `clockin v1 | <день UTC> | <wallet>`,
   приложение собирает транзакцию: `Secp256r1SigVerify` + Memo, кошелёк подписывает
   пальцем. Если железная подпись не сходится — транзакция не проходит вообще. Запись
   в цепочке = доказательство «в этот день этот кошелёк и этот физический Seeker были
   вместе и живы». Комиссия 5000 лампортов, платит владелец.
4. **Service Record** собирается из настоящих чисел: возраст SGT (дата минта из цепочки),
   verified duty days (счёт CLOCK IN-транзакций), серия, стаж в стейке (D-010),
   застейкано (уже умеем), .skr-имя. Block Stamps — вехи: первый клок-ин, 7, 30, 100 дней,
   первый стейк, первый выход и возврат.
5. **Поделиться** — карточка через `modules/skr-share`, без суммы (D-007).

## Что в релиз 2.0, по приоритету

1. Регистрация железа + NOT A SEEKER (ядро Witness).
2. Service Record с привязкой SGT и кошелька, Genesis-транзакция.
3. CLOCK IN + история + серия + напоминание в выбранный час (expo-notifications есть).
4. Карточка и поделиться.
5. `Unstake` / `Withdraw` через MWA с симуляцией — если успеваем к 1 октября.
6. Будильник созревания — если успеваем.

**Вырезано из 2.0:** компаунд одним пальцем, кран, гильдии (D-005), Network Weight,
difficulty, эпохи, BLE-свидетели, кланы. Всё это — развитие после 8 октября.

## Демо на две минуты

Seeker → VERIFY MY SEEKER → семь зелёных строк → CREATE MY SERVICE RECORD → палец →
карточка → CLOCK IN → палец → день появился в истории, ссылка на транзакцию →
эмулятор → NOT A SEEKER.

## Амбиция «сеть, которая живёт на стейкинге SKR» — честно

Для хакатона: сеть = все зарегистрированные Seeker'ы, публичная страница на
`skr.alexkosa.dev`: сколько Seeker'ов верифицировано, сколько клок-инов сегодня,
Genesis-запись №1 — Seeker Alexа. Аттестор один — наш сервер, и это написано прямо.

После хакатона: аттесторов становится несколько, и роль аттестора — это то, что по
замыслу Solana Mobile делают Гардианы со стейком SKR. Мы соединяем их собственные
компоненты. Ни выплат за стаж, ни эмиссии, ни «майнинга» не обещаем (стоп-кран 5,
MiCA ст. 4(3) — токен за данные не считается бесплатным).
