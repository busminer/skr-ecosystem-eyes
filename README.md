# SKR Eyes

A Solana Mobile app for people who stake SKR. The vault is drawn alive: every
stake falls in as a phone with the staker's `.skr` name, every exit hangs above
the pile and cools for its 48 hours. Under it, the live feed of finalized moves,
your own card with its real age and what it has earned, unlock alerts set on the
phone itself, and staking straight from the phone through the Mobile Wallet
Adapter. Eleven languages.

**Stake SKR. See everything.**

- App: `dev.alexkosa.skreyes` — version 1.1.0 (versionCode 6), in the Solana dApp Store since 04.09.2026
- Site, privacy and support: <https://skr-eyes.alexkosa.dev>
- Data comes from the public API at <https://skr.alexkosa.dev>

This project is **not affiliated with the Solana Foundation or Solana Mobile.**

## What is in this branch

| Path | What it is |
|---|---|
| `App.tsx`, `src/` | The app itself |
| `plugins/` | Expo config plugin that wires the release signing config |
| `patches/` | `patch-package` fixes applied on top of the dependencies |
| `scripts/probe/` | Offline proof that the stake transaction bytes are correct |
| `site/` | The static site: overview, privacy, terms, support |
| `store/` | dApp Store listing text, release notes per version, and the script that draws the media |
| `src/lab/` | The screens: `VaultScene` and `vaultSceneHtml.ts` (the living vault in a WebView), `FlowLab`, `MyLab`, `AlertsLab`, the staker card and the stake flow |
| `src/strings/` | The eleven languages |
| `assets/`, `brand/` | Icon, splash, sounds and the sources they are generated from |

`android/` is not committed: it is generated by `expo prebuild -p android`.

## Building a release

Needs JDK 17 and the Android SDK.

```bash
npm install            # runs patch-package afterwards
npx expo prebuild -p android
```

The release keystore is read from the environment. Export each variable on its
own line — chaining them in a single `export` leaves the later ones empty and
the build fails with `Given final block not properly padded`.

```bash
export SKR_EYES_KEYSTORE_PATH="/absolute/path/to/skr-eyes-release.jks"
export SKR_EYES_KEY_ALIAS="skr-eyes-release"
export SKR_EYES_KEYSTORE_PASSWORD="…"
export SKR_EYES_KEY_PASSWORD="$SKR_EYES_KEYSTORE_PASSWORD"
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

Without those variables the build is signed with the debug key and the store
will reject it; Gradle prints a warning saying exactly that.

Signed APKs live in `builds/`, which is not committed. The 1.0.0 APK is
attached to the `v1.0.0` release. The release notes for every version are in
`store/RELEASE-<version>.md`.
